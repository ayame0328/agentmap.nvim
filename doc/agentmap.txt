1. INTRODUCTION                                                *agentmap-intro*

agentmap.nvim draws the agents that Claude Code starts (parent, children,
grandchildren) as a map from START through stages to END, inside Neovim.
The map updates while Claude Code works; runs are kept for later.

Claude Code calls a small recorder (`bin/agentmap-collect`, Python 3) through
its hooks. The recorder appends one short line per event to a file in the
record folder; Neovim reads that file. The recorder never fails and never
changes what Claude Code does, except to deliver a steering instruction you
wrote (|agentmap-steer|) and to hold an agent you paused (|agentmap-pause|).

Requirements: Neovim 0.10+, Python 3, Claude Code (verified with 2.1.283 to
2.1.291). Optional: git, oil.nvim, a Chromium-based browser for PDF export.
Windows-native Neovim is experimental.

==============================================================================
2. SETUP                                                       *agentmap-setup*

Install with your plugin manager. `setup()` is optional. Then once:

1. |:AgentMapInstallHooks| registers the recorder in Claude Code's
   settings.json (shows a diff and asks first; keeps a backup).
2. `:checkhealth agentmap` checks everything.
3. Start a new Claude Code session; recording starts there.
4. Paste the writing convention into your CLAUDE.md (|agentmap-convention|).

Claude Code in a container: see `docs/containers.md` in the plugin folder.

After upgrading from 0.1.0, run |:AgentMapInstallHooks| again: 0.1.1 records
TaskCreate / TaskUpdate / TaskList, adds a synchronous PreToolUse hook, and
makes SubagentStop synchronous. `:checkhealth agentmap` says "outdated" until
then. Run it again after changing `steer.mode`.

After upgrading from 0.1.1 to 0.1.2, run it again as well: the delivery hooks
get `--pause` and a 630 s timeout, steering is delivered when an agent tries
to finish (the 0.1.1 registration hands it over at the next tool call as a
tool error, which current models may ignore), and SendMessage is recorded.
Until then `x`, `X` and `s` on a sub-agent refuse; recording and the terminal
routes keep working.

3. COMMANDS                                                 *agentmap-commands*

:AgentMap [{session_id} [{prompt_id}]]                             *:AgentMap*
        Open the map of the latest prompt that started agents, and follow
        new runs. With arguments, open that run (and prompt) and stay on it.

:AgentMapRuns                                                  *:AgentMapRuns*
        Pick a past run, or a Claude Code session to import.

:AgentMapAgent {n|id}                                         *:AgentMapAgent*
        Details of agent number {n} in the map, or of the agent {id}.

:AgentMapRefresh                                            *:AgentMapRefresh*
        Read the records again.

:AgentMapExport [{format} [{path}]]                          *:AgentMapExport*
        Export the prompt shown in the map. {format} is `markdown`, `html`
        or `pdf`; without it you are asked. See |agentmap-export|.

:AgentMapReview {n|id} {verdict} [{reason}]                  *:AgentMapReview*
        Record a review. {verdict} is PASS, RETRY, ESCALATE or SUBMIT.

:AgentMapInstallHooks [{settings.json}]                *:AgentMapInstallHooks*
        Register the recording hooks. Other settings and hooks are kept.
        Running it again changes nothing.

:AgentMapImport [{session_id}]                               *:AgentMapImport*
        Import a run from Claude Code's transcript (default: the newest
        session of the current folder).

:AgentMapSteer {n|id} [relay] [{text}]                        *:AgentMapSteer*
        Send a steering instruction to agent number {n} (or ROOT, or the
        agent {id}). Without {text} the editor window opens. With `relay`
        first, the text is typed into the main agent's terminal for it to
        pass on with SendMessage right away (a running direct sub-agent of
        the main agent only; refused without a Claude terminal). See
        |agentmap-steer|.

:AgentMapPause {n|id} [next|stop]                             *:AgentMapPause*
        Pause agent number {n} (or ROOT, or the agent {id}). `next` (the
        default) stops it at its next tool call or when it finishes,
        whichever comes first; `stop` only when it finishes. On an agent
        that already has a pause it tells how it stands (a different place
        replaces a pause that has not stopped the agent yet); it never
        resumes. A box waiting at the gate gets the Pass / Fix menu.
        See |agentmap-pause|.

:AgentMapResume {n|id}                                       *:AgentMapResume*
        Resume a paused agent, withdraw a pause that has not stopped it yet,
        or let a box waiting at the gate pass.

:AgentMapGate [on|off]                                         *:AgentMapGate*
        Turn the gate of the run on screen on or off (no argument: toggle).
        See |agentmap-gate|.

4. KEYS                                                         *agentmap-keys*

All keys are local to the map and side buffers. No global mapping is made
unless `keymaps = { global = true }` (adds <leader>aa, <leader>ar, <leader>ae).

Map:
  1-9        details of agent number n
  <CR>       details of the box under the cursor (HUMAN CHECK: the question)
  n / p      next / previous box
  + / -      expand / collapse children
  z / <BS>   only this agent and below / back up
  t          transcript          d    git diff        w    working folder
  a          review              e    export          r    reload
  R          past runs           v    map / list      ?    key list
  s          steer (|agentmap-steer|)                 q    close
  x          pause / resume (gate: Pass / Fix menu, |agentmap-pause|)
  X          gate of this run on / off (|agentmap-gate|)

Detail, transcript and diff views:
  <BS>       back               q     close
  <CR>       open the agent / parent / HUMAN CHECK on the line; on a
             steering line, show or hide its full text
  t d w a s x  as in the map

5. CONFIGURATION                                              *agentmap-config*

>lua
  require("agentmap").setup({
    lang = "en",              -- "en" | "ja" (or vim.g.agentmap_lang)
    root = nil,               -- nil: $AGENTMAP_DIR, then stdpath("data").."/agentflow"
    claude_config_dir = nil,  -- nil: $CLAUDE_CONFIG_DIR, then ~/.claude
    python = nil,             -- nil: python3, python, py -3
    open = "tab",             -- "tab" | "vsplit" | "current"
    mode = "auto",            -- "box" | "tree" | "auto"
    keymaps = { global = false },
    review = { provider = "auto", rubric = nil },
    export = { html_command = nil, pdf_command = nil },
    progress = {              -- false: { enabled = false }
      enabled = true,         -- % in the boxes (details/exports keep it)
      tick_ms = 1000,         -- redraw interval while something runs
      default_ms = 600000,    -- typical agent time without history
      min_samples = 3,        -- agents needed for a type+model median
      no_steps = "time",      -- no step list: "time" (max 95.0) | "none"
      log = true,             -- <root>/progress_log.jsonl
    },
    animation = {             -- false: { enabled = false }
      enabled = true, frame_ms = 100, period = 6, tail = 2,
      back_ms = 3000,         -- light flowing back after an agent finishes
      max_paths = 40,
    },
    steer = {                 -- false: { enabled = false }
      enabled = true,
      mode = "stop",          -- "stop" (when the agent tries to finish)
                              -- | "deny" | "context" (also at its next tool
                              -- call; current models may ignore it)
      relay = "menu",         -- "menu" | "always" | "never"
      root_via = "terminal",  -- "terminal" | "hook"
      no_terminal = "stop",   -- "stop" | "clipboard" | "none" ("hook": "stop")
      submit_delay_ms = 300,   -- Enter this many ms after the text (0: one write)
      input = "window",       -- "window" | "line"
      text_max = 4000,
    },
    pause = {                 -- false: { enabled = false }
      enabled = true,         -- false: no pause in the hook command
      auto_resume_s = 600,    -- seconds until a pause resumes itself
      gate = false,           -- gate of a run you start watching
      release_on_exit = false, -- true: closing Neovim resumes all pauses
      notify = true,          -- notices: paused / at the gate / resumed
    },
  })
<
The full list with defaults is in the README. `steer.mode` and
`pause.auto_resume_s` are written into the hook command (the latter also into
its timeout); run |:AgentMapInstallHooks| after changing them.
`steer.at_stop` is ignored since 0.1.2 (delivery at the end is always on).

6. WRITING CONVENTION                                     *agentmap-convention*

The map shows why an agent was started and what it reported only when Claude
writes them in a fixed form; nothing is guessed. The parent's prompt starts
with three lines:
>
  [Goal] what this is for
  [Why delegate] why it is delegated
  [Done when] what has to come back
<
The child ends with `## Report` (`Done:`, `Approach:`, `Why:`, `Open issues:`)
or, when it needs a decision, `## Needs confirmation` (`Working on:`,
`Blocked at:`, `Question:`, `Options:`). Japanese markers (【目的】, ## 報告, ...)
are always accepted too. The text to paste into CLAUDE.md is in
`docs/writing-convention.md`.

Step list (read as progress, |agentmap-progress|): the child writes `## Steps`
and a numbered list (3-8 steps) in its first reply, then a line `Step N done`
after each step (Japanese: `## 手順`, `手順 N 完了`). The main agent keeps its
list with TaskCreate / TaskUpdate; sub-agents cannot use those tools in Claude
Code 2.1.288.

==============================================================================
7. HUMAN CHECK                                            *agentmap-human-check*

When Claude asks you a question (AskUserQuestion), a HUMAN CHECK box appears:
purple [WAITING] until you answer, green [DONE] with the answer, grey
[UNANSWERED] if the turn ended without one. It is linked to the sub-agent
whose description is in the question.

==============================================================================
8. REVIEW                                                     *agentmap-review*

`a` in the map records PASS, RETRY or ESCALATE with a reason. Reviews go to the
run's records and to `<root>/review_log.jsonl`. A verdict provider can propose
a verdict; you always decide:
>lua
  require("agentmap.review").register("name", {
    available = function() return true end,        -- optional
    evaluate = function(ctx, cb) cb({ verdict = "PASS", reason = "..." }) end,
  })
<
==============================================================================
9. EXPORT                                                     *agentmap-export*

Markdown always works. HTML uses a bundled converter (or
`export.html_command`). PDF needs `export.pdf_command`, an argument list in
which %{html}, %{out} and %{title} are replaced, for example:
>lua
  export = { pdf_command = { "google-chrome", "--headless=new",
    "--no-pdf-header-footer", "--print-to-pdf=%{out}", "%{html}" } }
<
==============================================================================
10. RECORDS AND PRIVACY                                      *agentmap-privacy*

Records stay in the record folder on your disk: per event the ids, times,
tool names and file names, the first 200 characters of prompts, the three
convention lines, questions and answers, and the child's report (up to 2000
characters). Full prompts, tool output and file contents are not stored.
Strings that look like keys or passwords are replaced with `***`.
Step lists keep up to 60 characters per step (TaskCreate descriptions are not
stored). Steering instructions are stored as you wrote them (not redacted).
Pauses are recorded with their times and where the agent stopped; pause
files hold no text (`<agent>.hit.json` holds the tool name and tool_use_id
while the agent waits).

11. PROGRESS AND THE LIGHT                                 *agentmap-progress*

Each box shows a percentage next to its elapsed time:
>
  [RUNNING] ~62.4% 12:34      "~" = estimate
  [REVIEW] 66.6% 12:34        fact only
<
Fact: finished steps / all steps of the agent's step list (TaskCreate /
TaskUpdate for the main agent, `## Steps` in a sub-agent's transcript).
Estimate (`~`): only the running step, filled in with elapsed time / the
typical time of similar past agents (the median of your own records per
agent type and model; 10 minutes without history). A parent's running step
uses the average of its running children. Values are rounded down and stay
below 100 until the agent finishes. Boxes without a step list are estimated
from elapsed time only (at most 95.0); `progress.no_steps = "none"` shows no
number for them. A parent without a step list shows the plain average of its
children (finished = 100, not started yet = 0). The map is redrawn once a
second while something runs, and not while it is hidden or in another tab
page.

The light: in the map (box) view a dot of light runs along the line into each
[RUNNING] agent, from parent to child. When the agent finishes, the same line
flows back to the parent for `animation.back_ms` (3 s). The line into a HUMAN
CHECK that waits for your answer flows in purple. Only highlights move
(namespace `agentmap_anim`, priority 4200); the text is not changed, and the
timer stops when nothing is lit. The list (tree) view has no light.

Highlight groups (set with `default = true`, light and dark variants):
  AgentMapFlow1..3        light into a running agent (1 = head)
  AgentMapFlowBack1..3    light flowing back after it finished
  AgentMapFlowWait1..3    light into a HUMAN CHECK waiting for an answer

`progress = false` hides the numbers in the boxes; `animation = false` turns
the light off. Estimates are logged to `<root>/progress_log.jsonl` for later
checking (`progress.log`); `:checkhealth agentmap` shows the median error.

12. STEERING                                                  *agentmap-steer*

`s` on a box (or |:AgentMapSteer|) opens a menu, then a small window: write
the instruction, send with <C-s>, `:w` or <CR> in normal mode, cancel with
`q`.

  Running sub-agent    delivered when it tries to finish: its SubagentStop
                       hook holds the end once and hands it the text; it
                       applies it, continues and finishes again. Until then
                       it works on the old plan. Paused before a tool call:
                       the pause is lifted and the text arrives at its end.
                       Waiting at its end (the gate): the text arrives now.
  Relay (menu item 2)  only for a running direct sub-agent of the main
                       agent when its terminal is in this Neovim: typed into
                       the main agent's terminal as `[AgentMap] Tell
                       sub-agent [3] "<name>" (agent id <id>) this, with
                       SendMessage: <text>`; the main agent passes it on
                       with SendMessage and the sub-agent gets it at its
                       next tool call. Immediate, but followed less
                       reliably than an instruction at its end. Not
                       offered while the main agent is paused (`s` says
                       why): use its end, or resume the main agent first.
  Main agent (ROOT)    typed into the |terminal| running `claude` in this
                       Neovim as `[AgentMap] <text>` and Enter (a pause
                       before a tool call is lifted first). The one in the
                       run's folder (or a parent) is used; with several, or
                       only ones in other folders, you pick one. Without
                       such a terminal: `steer.no_terminal` ("stop": at the
                       end of its turn through its Stop hook, "clipboard"
                       or "none").
  Finished agent       a redo request is typed into the main agent's
                       terminal; nothing is marked as rework automatically.

At its end the model sees `Stop hook feedback:` followed by `[AgentMap]
Instruction from the user, typed in Neovim (AgentMap) while you were working.
It reaches you now, just before you finish: ...`. With Claude Code 2.1.291
sub-agents followed it 17 times out of 17 and the main agent 9 out of 9.
`steer.mode = "deny"` or "context" also delivers at the next tool call as a
tool result (`PreToolUse:<Tool> hook error: ...`); current models may ignore
that, so it is not the default.

When an instruction reaches a sub-agent at its end, its parent is told once,
by the same route as any instruction for that parent (not when it has
finished, and not for a relay).

The box shows ` ✎1` while instructions wait (a relay: until the main agent
passes it on), ` ✎` after delivery and ` ✎!` when the agent finished first,
the main agent ended its turn without passing a relay on, or Claude Code let
the agent finish past 8 held ends in a row (NOT HELD). The detail view
lists every instruction with its full text and, for a relay, SENT / READ /
RELAYED (the main agent's SendMessage is recorded; whether the sub-agent read
it is not); `s` -> "Cancel pending" withdraws one not yet delivered.
Undelivered text waits in `<run>/steer/<agent>-<ms>.json` (mode 0600). An
agent usually follows the instruction, but it is not guaranteed.

The text goes into the terminal as one line (control characters become
spaces; a trailing `\` gets a space after it, since Claude Code reads `\` +
Enter as a new line) and Enter follows
`steer.submit_delay_ms` (300 ms) later: Claude Code 2.1.289 treats a long
line (about 250 characters, a parent notice) that arrives in one write as a
paste and leaves it unsent in its input box. The detail view shows SENT until
Claude Code reads the line, then DELIVERED (read by Claude Code).

Nothing is sent, and a message says why, when the registered hooks are
outdated or use another `steer.mode` (`s` on a sub-agent: run
|:AgentMapInstallHooks| first; the terminal routes, relay included, are not
affected) or when the run has ended (`s` on the main agent or a finished
agent would reach another conversation's terminal in the same folder; give
new instructions in Claude Code itself).

13. PAUSING AND THE GATE                                      *agentmap-pause*

`x` on a running box (or |:AgentMapPause|) pauses that agent; `x` again
resumes it. Nothing is cancelled: the agent stops at its next tool call or
when it tries to finish, whichever comes first, and waits there. ROOT can be
paused too. Only that agent stops; other sub-agents go on.

The synchronous hooks (PreToolUse, SubagentStop, Stop) find the pause file
`<run>/pause/<agent>.json` and wait inside Claude Code, checking it every
100 ms, until Neovim removes it. Resumed without an instruction, the agent
sees nothing (the held tool call just runs). `s` on a box paused before a
tool call resumes it; the instruction arrives when it tries to finish (ROOT:
the pause is lifted, then the text is typed into its terminal). At the gate,
"Fix" (or `s` on a box paused at its end) hands the text over on the spot,
with one more line, `(You were paused by the user for 2 min 31 s before this
instruction.)`.

The box shows [PAUSED] (orange, `AgentMapPaused`) while the agent waits and
` ⏸` (`||` where it is drawn wide) while the pause waits to be reached; the
light on its line stops. Claude Code shows `running PreToolUse hooks...` in
its spinner for a paused main agent and nothing for a paused sub-agent.

A pause left alone resumes by itself after `pause.auto_resume_s` (600 s).
The hook keeps the deadline by the wall clock, so it holds when Neovim is
closed or the computer sleeps. Claude Code stops a hook after its `timeout`
(600 s when none is set) and then runs the tool silently, so the delivery
hooks are registered with `auto_resume_s + 30` (630 s). Run
|:AgentMapInstallHooks| after upgrading to 0.1.2: with the old registration
`x`, `X` and `s` on a sub-agent refuse, while recording and the terminal
routes keep working.

Esc in Claude Code interrupts the main agent's turn only; a pause on ROOT
stays placed and stops it again at its next tool call. Closing Neovim does
nothing by default (`pause.release_on_exit = true` resumes every pause of the
run on screen). When Claude Code exits, the waiting hook ends and the pause
is recorded as ended; at the end of a session the recorder removes that
run's pause files (and the flag when none is left anywhere).

Cost: nothing paused, 1-2 ms per tool call as before; while any pause file
exists (always while a gate is on), about 15-20 ms per tool call. When the
last pause resumes by itself the hook also removes the flag. Files:
`<run>/pause/<agent>.json` (0600), `<agent>.hit.json` (written by the hook),
`<run>/pause/GATE`, and the flag `<root>/pause.pending`.

                                                               *agentmap-gate*
`X` (or |:AgentMapGate|) turns the gate of the run on screen on or off
(`pause.gate` is the value for runs you start watching; the state is kept in
the run's folder). While it is on, every running sub-agent (not ROOT) waits
when it tries to finish; the box shows [GATE] and its report can already be
read with <CR>. `x` on it offers:
  Pass            let it finish; the parent gets the report
  Fix             write an instruction; the agent continues and waits again
                  at its next end (Claude Code allows 8 holds in a row;
                  past that the text is handed over but the agent ends:
                  the detail view says NOT HELD)
  Keep waiting    show the report
Left alone it passes after 10 minutes. Turning the gate off lets every
waiting agent pass.
