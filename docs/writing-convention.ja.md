# 書き方の決まり

agentmap.nvim は、Agent を**なぜ**任せたか、**何を報告したか**、**何を聞いてきたか**を画面に出します。
推測はしません。Claude に書いてもらう決まった目印だけを読みます。この形で書かれていない項目は
「（書かれていません）」と表示されます。

決まりは 3 つです。

1. 親が子（Agent）に渡す指示は、`【目的】` `【任せる理由】` `【期待する結果】` の 3 行で始める。
2. 子は最後に `## 報告` を書く（人の判断が要るときは `## 要確認`）。
3. 子のことで Claude があなたに質問する（AskUserQuestion）ときは、質問にその子の名前を入れ、
   選択肢ごとに選んだ後の進め方（`→ 選んだら: 〜`）を書く。

日本語と英語の目印は、いつでも両方使えます。混ぜても構いません
（英語版：[writing-convention.md](writing-convention.md)）。

## CLAUDE.md に貼る文

```markdown
## Agent に任せる・報告する・人に確認するときの書き方（agentmap.nvim が読む決まり）

agentmap.nvim は次の見出しと項目名を機械的に読んで Neovim の画面に出す。
書かれていない項目は「（書かれていません）」と表示され、推測で補われない。

**親（Agent を起動する側）：指示文の先頭 3 行**。この順・この文字（全角の【】）で始め、その後に本文を書く。

【目的】何のためにやるか（1 行）
【任せる理由】なぜ自分でやらず任せるか（1 行）
【期待する結果】何が返ってくれば完了か（1 行）

**子（起動された側）：最後の報告**。SubagentHandback で返す場合も、その message の中にこの形で書く。

## 報告
- やったこと: 何をしたか
- 方向: どういう方針で進めたか
- 理由: なぜその方針にしたか
- 残った課題: 無ければ「なし」

**子：人の確認が要るとき**。子は利用者に直接は聞けない。作業を止め、報告の代わりにこれを書いて終わる。

## 要確認
- 今の作業: 何をしていたか
- 止まっている所: どこで先に進めないか
- 確認したいこと: 聞きたいことを 1 文で
- 選択肢:
  1. 名前 → 選んだ後の進め方
  2. 名前 → 選んだ後の進め方

**親：子の要確認を受けて AskUserQuestion するとき**

- question は「<子に付けた description> について：<確認したいこと>」の形にする
- header は description の先頭（12 文字まで）
- 各 option の label は子の選択肢の名前をそのまま。description の末尾に「→ 選んだら: <進め方>」を入れる
- 自分の判断で直接聞くときも同じ形（「〜について：」の部分は不要）
- 答えが出たら、その答えに沿って続ける。子を起動し直すときは【目的】に「<答え> を選んだため」と書く
```

## 読み取りの規則

同じ規則を 2 か所で実装しています。Lua（`lua/agentmap/brief.lua`：画面表示と会話記録の取り込み）と
Python（`bin/agentmap-collect`：hooks の記録）です。試験用の例 `tests/fixtures/convention_cases.jsonl` を
両方に流して、結果が同じであることを確かめています。

### 親の指示

| 項目 | 日本語の目印 | 英語の目印 |
|---|---|---|
| purpose | `【目的】` | `[Goal]` |
| reason | `【任せる理由】` | `[Why delegate]` |
| expected | `【期待する結果】` | `[Done when]` |

- 英語の目印は大文字・小文字を区別しない（`[goal]` でもよい）。
- 目印は指示文のどこにあってもよい。同じ項目が 2 回以上あれば、言語を問わず最初のものを使う。
- 値は、目印の直後から「次の改行」「次の `【`」「次の英語の目印」のうち最も近いところまで。
  3 つを 1 行に続けて書いても読める。
- 目印の直後の `:` / `：` は落とし、前後の空白も落とす。
- 1 項目は 300 文字で切る。
- 3 つとも無い（または全部空）なら、その指示には「任せた理由」が無いものとして扱う。

### 子の報告

| | 日本語 | 英語 |
|---|---|---|
| 報告の見出し | `## 報告` | `## Report` |
| 項目 | `やったこと` / `方向` / `理由` / `残った課題` | `Done` / `Approach` / `Why` / `Open issues` |
| 要確認の見出し | `## 要確認` | `## Needs confirmation` |
| 項目 | `今の作業` / `止まっている所` / `確認したいこと` / `選択肢` | `Working on` / `Blocked at` / `Question` / `Options` |

- 見出し：`#` が 2〜3 個、見出しの語、その後ろは行末・空白・`(` `（`・`:` `：` のどれか。
  `## 報告書`・`# 報告`・`#### 報告` は見出しではない。
- 項目：行頭の `-` `*` `・` と `**太字**` は付けても付けなくてもよい。項目名の後ろに `:` か `：`。
- 英語の見出し・項目名は大文字・小文字を区別しない。どちらの言語の見出しの下でも、両方の言語の項目名を読む。
- 項目の本文は次の項目まで続く（複数行は空白でつなぐ）。空行が 2 つ続いたら節は終わり。
- 両方の見出しがあれば、後に出てきた方を読む。
- 選択肢：`1. 名前 → 進め方`・`1. 名前 -> 進め方`・`1) 名前 → 進め方`・全角の `１．`。矢印の後ろは無くてもよい。

### HUMAN CHECK（AskUserQuestion）

- 選択肢の description：`本文 → 選んだら: 進め方` または `本文 -> if chosen: 進め方`。矢印 2 種と言葉 2 種は
  どの組み合わせでもよい（`→ if chosen:`・`-> 選んだら:`）。`if chosen` は大文字・小文字を区別しない。
  言葉が続かない矢印は本文の一部として扱う。
- 質問と子の結び付けは「質問文に子の description が入っているか」で決める（言語に依らない）。
  画面では、先頭の `<description> について：` / `<description>: ` を外して表示する。

## 記録に残るもの

記録係が残すのは、読み取った 3 項目（purpose・reason・expected）、指示文の先頭 200 文字、子の報告の本文
（2000 文字まで。鍵やパスワードらしい部分は伏せる）だけです。指示文の全文は残しません。
